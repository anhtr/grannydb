# ADR 0027 — A hand-written service worker, and what it is allowed to cache

**Status:** accepted · 2026-09-17

## Context

[ADR 0026](0026-last-known-good-snapshot-for-offline-reads.md) gives the app something to *show*
offline. It does not make the app *open* offline: a cold start still fetches `index.html` and the JS
bundle from GitHub Pages, and on a plane that fetch never completes. The HTTP cache might cover it
and might not; it is not a guarantee you can plan a flight around.

The stated use case is crocheting away from signal, which on a phone means the app has to be on the
home screen, not in a browser tab someone has to remember not to close.

## Options

**`vite-plugin-pwa` (Workbox).** The default answer, and it generates a correct worker with revision
hashes, cleanup and update flow handled. It also puts a generated third-party runtime script on an
origin that holds a GitHub token in `localStorage` and is shared with every other project page under
the same github.io user. The repo has four production dependencies and an explicit invariant about
no third-party runtime script, for exactly that reason.

**No service worker; rely on the HTTP cache.** Free, and sometimes works. "Sometimes works" is not a
feature you can use on a plane.

**A hand-written worker.** The app is a single HTML document (hash routing — [ADR
0007](0007-stack-and-hash-routing.md)) plus one hashed JS file and one hashed CSS file. There is no
runtime routing to generalise, no revision manifest to maintain — content hashes already *are* the
revisions. That makes the whole worker about seventy lines.

## Decision

Ship `src/sw/sw.js` as plain JS. A Vite plugin substitutes the hashed filenames and a version
derived from them at build time, since that is the only point where the names are known, and emits
`dist/sw.js`.

**What it caches: the shell, and nothing else.** The document and the hashed JS/CSS. Explicitly not:

- anything cross-origin — the `fetch` handler returns without calling `respondWith`, so the GitHub
  API is not merely uncached, it is untouched. No authenticated response can ever land in a cache on
  a shared origin.
- `data/bundle.json` — data offline is [ADR
  0026](0026-last-known-good-snapshot-for-offline-reads.md)'s job. Two caches over the same rows
  would mean two answers to "how old is this", and the app could only show one of them.
- sourcemaps.

Plus a web manifest and icons, so it installs to a home screen. Manifest URLs are relative, so
nothing hardcodes `/grannydb/` and a `BASE_PATH` build still resolves (invariant 5). The icons are
generated by a committed script rather than a design tool — a granny square is concentric bands of
colour, which is fifteen lines of pixel arithmetic and a zlib stream, both already in Node.

## Consequences

- The app opens with no network, from the home screen, and keeps working.
- A precached shell can be one deploy behind. The worker does not `skipWaiting` on its own: swapping
  the running app out mid-edit is worse than being an hour old. A waiting worker surfaces as an
  "A newer version is ready" bar, and taking it is a tap.
- Precache entries are content-hashed, so a cache hit needs no revalidation and `activate` can
  delete every older `grannydb-*` cache outright.
- The worker is registered in production only; in development it actively unregisters, so a worker
  from `npm run preview` cannot shadow the dev server on the same machine.
- The CSP in `index.html` gains `worker-src 'self'` and `manifest-src 'self'`. Both already fell
  back to `default-src 'self'`, but that file states its directives rather than relying on
  fallbacks.
- **On iOS an installed web app has its own storage, separate from Safari's.** The token has to be
  pasted once inside the installed app, and its queue is a different queue from the tab's. That is a
  platform property, not something the app can paper over, so operations documents it.
- Debugging gains a step: a stale shell is now a possible explanation for "my change isn't there",
  and the answer is the update bar or Settings → Reload from GitHub.
